# ردّ — إدارة العملاء ومساعدي ماسنجر

لوحة إدارة عربية متعددة العملاء على Cloudflare Workers. الإصدار 2.0. تم تجهيز النظام والتوقف قبل ربط صفحات ميتا ومفاتيحها.

## وظائف جاهزة
- إضافة وتعديل العملاء: اسم النشاط والمسؤول والتواصل والحالة ومعرف الصفحة اختياريًا.
- ملف معلومات مستقل لكل نشاط: المنتجات والأسعار والمواعيد والسياسات.
- الباقات والأسعار ورسوم التأسيس والعملة وتاريخ نهاية الاشتراك.
- حدود يومية وشهرية مستقلة لمحاولات الرد، وعدّ التوكنات التي يعيدها المزود.
- بحث ومؤشرات عدد العملاء والاشتراكات النشطة وقيمة الأسعار الشهرية المسجلة. لا تحصيل مالي فعلي.
- إعدادات مزود عامة: رابط HTTPS واسم النموذج وصيغة max_tokens أو max_completion_tokens. مزود واحد مشترك بين العملاء حاليًا.
- تجربة إجابات داخل اللوحة بعد إضافة المفتاح، دون إرسال الرسالة إلى ماسنجر.
- إيقاف واستئناف محادثة محددة باستخدام PSID لكل نشاط مستقل.
- دخول الإدارة بجلسة HttpOnly لمدة 8 ساعات وحد لمحاولات الدخول وحماية من طلبات الكتابة العابرة للمواقع.
- بيانات العملاء في Durable Objects؛ تاريخ المحادثات وحدود الاستخدام منفصلة حسب العميل التجاري ومعرف المحادثة.

## المطلوب الآن للنشر فقط
حساب Cloudflare قادر على نشر Workers ودعم Durable Objects بالخطة المتاحة في الحساب. مفتاح الذكاء الاصطناعي غير مطلوب لنشر لوحة الإدارة أو إضافة العملاء.

```bash
npm ci
npx wrangler login
npx wrangler secret put ADMIN_TOKEN
npm run deploy
```

حدد كلمة دخول إدارة طويلة وخاصة عند طلب ADMIN_TOKEN. لا تضعها في GitHub. لا تُفعّل اشتراكًا مدفوعًا تلقائيًا إذا طلب الحساب ذلك.

بعد النشر افتح الرابط الرئيسي وسجل الدخول ثم أضف العملاء. لا يوجد تسجيل ذاتي أو حسابات دخول منفصلة للعملاء في هذه النسخة؛ اللوحة لصاحب النظام.

## مفتاح الوسيط — لاحقًا
عندما تكون جاهزًا لاختبار الرد، أضف مفتاح مزودك كسر:

```bash
npx wrangler secret put OPENAI_API_KEY
```

افتح «مزود الذكاء الاصطناعي» واضبط base URL الذي يعطيه الوسيط، مثل `https://provider.example/v1`، واسم النموذج الصحيح. النظام يرسل إلى `/chat/completions`. لا تفترض أن أي مفتاح وسيط سيعمل بدون معرفة الرابط والنموذج وصيغة حد الإجابة. يدعم النصوص فقط، ولا يدعم واجهات Claude/Gemini الأصلية غير المتوافقة أو استيراد الرصيد من لوحة الوسيط.

الوسيط يتلقى بيانات النشاط وسؤال العميل والتاريخ المختصر عند التشغيل؛ اختره وفق اتفاقك مع العميل. لا توجد نسخ مفاتيح على الواجهة ولا في ملفات المستودع.

## نقطة التوقف: الربط
لم تُدخل مفاتيح Meta ولم تُربط أي صفحة ولم تُرسل رسائل فعلية. رابط Webhook لكل عميل هو `/webhook/CLIENT_ID`؛ يعيد 503 حتى اكتمال الربط. حفظ معرف الصفحة أو تفعيل مربع تشغيل البوت لا يفتح الربط.

المرحلة التالية تحتاج تنفيذ إدخال آمن ومشفر لمفاتيح الربط لكل عميل (App Secret وPage Access Token وVerify Token)، وتسجيلها في مخزن العميل، ثم إعداد Webhook في Meta ومراجعة الصلاحيات ووضع Live حسب نوع التطبيق. لا توجد واجهة لإدخال هذه المفاتيح بعد، عمدًا للتوقف عند هذه المرحلة. راجع GRAPH_VERSION في تطبيق ميتا قبل فتح الربط.

## الاختبارات
```bash
npm test
npm run build-ui
npx wrangler deploy --dry-run
node scripts/verify-runtime.mjs
```

الاختبارات تختبر التوقيع، صلاحيات الإدارة، عزل العملاء وحدودهم، إعدادات الوسيط، عدم احتساب تجربة بلا مفتاح، عدم إرسال التجربة لماسنجر، وإغلاق الربط. الاختبار الإضافي يشغّل workerd/Miniflare بمخزن Cloudflare الفعلي محليًا، وبيانات اختبار مؤقتة.

## التشغيل المحلي
انسخ `.dev.vars.example` إلى `.dev.vars` وحدد كلمة إدارة للاختبار فقط:
```bash
npm run dev
```

إذا كانت بيئة التشغيل لا تسمح لـ Wrangler بقراءة عناوين واجهات الشبكة، يظل اختبار `verify-runtime` مفيدًا دون خادم التطوير. لا تخلط نجاح اختبارات API مع اختبار بصري للواجهة أو ربط ماسنجر حقيقي.

## حدود النسخة الحالية
- لا واتساب، لا بوابة دفع، لا فواتير آلية، ولا إرسال حملات.
- الحد اليومي والشهري يستخدم UTC ويحسب المحاولات والتجارب؛ ليس حدًا ماليًا. حدد حد الإنفاق عند الوسيط أيضًا.
- حالة اشتراك نشط لا تعني أن الصفحة مربوطة. البوت يحتاج حالة active ومربع السماح بالتشغيل واشتراكًا غير منتهي وربطًا مكتملًا.
- الحد الأقصى 500 نشاط في نسخة التخزين الحالية؛ كل سجل منفصل لتجنب حدود حجم قيمة التخزين.
- الأسعار مسجلة يدويًا، وليست بيانات عن مبالغ محصلة أو أرباح.
- ذاكرة البوت آخر 6 رسائل؛ تبقى حتى الحذف. اتفق على سياسة الاحتفاظ قبل التشغيل التجاري. حذف بيانات محادثة يتم عبر POST `/api/clients/ID/contact-delete` مع sender، من جلسة الإدارة.
- طلب موظف أو مرفق يوقف الرد الآلي؛ الموظف يتابع صندوق وارد الصفحة. الرد اليدوي لا يوقفه تلقائيًا؛ استخدم لوحة تدخل الموظف.
- فشل إرسال ميتا أو غموضه يوقف المحادثة، ولا توجد إعادة إرسال تلقائية. قد يُفقد رد إذا تعطلت العملية بين إخراج المهمة من المخزن والإرسال؛ لا يوجد ضمان تسليم مرة واحدة.
- لا توجد تنبيهات أو لوحة تفاصيل لكل الرسائل في هذه النسخة.
- الخطة المجانية خاضعة لحدود حساب Cloudflare؛ استهلاك الوسيط مدفوع، ولا توجد ضمانة استخدام مجاني بلا حدود.
