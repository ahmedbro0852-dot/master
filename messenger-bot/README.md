# ردّ — إدارة العملاء ومساعدي ماسنجر

لوحة إدارة عربية متعددة العملاء على Cloudflare Workers. الإصدار 2.0. تم تجهيز النظام والتوقف قبل ربط صفحات ميتا ومفاتيحها.

## وظائف جاهزة
- إضافة وتعديل العملاء: اسم النشاط والمسؤول والتواصل والحالة ومعرف الصفحة اختياريًا.
- ملف معلومات مستقل لكل نشاط: المنتجات والأسعار والمواعيد والسياسات.
- الباقات والأسعار ورسوم التأسيس والعملة وتاريخ نهاية الاشتراك.
- حدود يومية وشهرية مستقلة لمحاولات الرد، وعدّ التوكنات التي يعيدها المزود.
- بحث ومؤشرات عدد العملاء والاشتراكات النشطة وقيمة الأسعار الشهرية المسجلة. لا تحصيل مالي فعلي.
- إعدادات مزود عامة: رابط HTTPS واسم النموذج وصيغة max_tokens أو max_completion_tokens. مزود واحد مشترك بين العملاء حاليًا.
- تجربة إجابات داخل اللوحة بعد إضافة المفتاح، دون إرسال الرسالة إلى ماسنجر.
- إيقاف واستئناف محادثة محددة باستخدام PSID لكل نشاط مستقل.
- دخول الإدارة بجلسة HttpOnly لمدة 8 ساعات وحد لمحاولات الدخول وحماية من طلبات الكتابة العابرة للمواقع.
- بيانات العملاء في Durable Objects؛ تاريخ المحادثات وحدود الاستخدام منفصلة حسب العميل التجاري ومعرف المحادثة.

## المطلوب الآن للنشر فقط
حساب Cloudflare قادر على نشر Workers ودعم Durable Objects بالخطة المتاحة في الحساب. مفتاح الذكاء الاصطناعي غير مطلوب لنشر لوحة الإدارة أو إضافة العملاء.

```bash
npm ci
npx wrangler login
npx wrangler secret put ADMIN_TOKEN
npm run deploy
```

حدد كلمة دخول إدارة طويلة وخاصة عند طلب ADMIN_TOKEN. لا تضعها في GitHub. لا تُفعّل اشتراكًا مدفوعًا تلقائيًا إذا طلب الحساب ذلك.

بعد النشر افتح الرابط الرئيسي وسجل الدخول ثم أضف العملاء. لا يوجد تسجيل ذاتي أو حسابات دخول منفصلة للعملاء في هذه النسخة؛ اللوحة لصاحب النظام.

## مفتاح الوسيط — لاحقًا
عندما تكون جاهزًا لاختبار الرد، أضف مفتاح مزودك كسر:

```bash
npx wrangler secret put OPENAI_API_KEY
```

افتح «مزود الذكاء الاصطناعي» واضبط base URL الذي يعطيه الوسيط، مثل `https://provider.example/v1`، واسم النموذج الصحيح. النظام يرسل إلى `/chat/completions`. لا تفترض أن أي مفتاح وسيط سيعمل بدون معرفة الرابط والنموذج وصيغة حد الإجابة. يدعم النصوص فقط، ولا يدعم واجهات Claude/Gemini الأصلية غير المتوافقة أو استيراد الرصيد من لوحة الوسيط.

الوسيط يتلقى بيانات النشاط وسؤال العميل والتاريخ المختصر عند التشغيل؛ اختره وفق اتفاقك مع العميل. لا توجد نسخ مفاتيح على الواجهة ولا في ملفات المستودع.

## نقطة التوقف: الربط
لم تُدخل مفاتيح Meta ولم تُربط أي صفحة ولم تُرسل رسائل فعلية. رابط Webhook لكل عميل هو `/webhook/CLIENT_ID`؛ يعيد 503 حتى اكتمال الربط. حفظ معرف الصفحة أو تفعيل مربع تشغيل البوت لا يفتح الربط.

المرحلة التالية تحتاج تنفيذ إدخال آمن ومشفر لمفاتيح الربط لكل عميل (App Secret وPage Access Token وVerify Token)، وتسجيلها في مخزن العميل، ثم إعداد Webhook في Meta ومراجعة الصلاحيات ووضع Live حسب نوع التطبيق. لا توجد واجهة لإدخال هذه المفاتيح بعد، عمدًا للتوقف عند هذه المرحلة. راجع GRAPH_VERSION في تطبيق ميتا قبل فتح الربط.

## الاختبارات
```bash
npm test
npm run build-ui
npx wrangler deploy --dry-run
node scripts/verify-runtime.mjs
```

الاختبارات تختبر التوقيع، صلاحيات الإدارة، عزل العملاء وحدودهم، إعدادات الوسيط، عدم احتساب تجربة بلا مفتاح، عدم إرسال التجربة لماسنجر، وإغلاق الربط. الاختبار الإضافي يشغّل workerd/Miniflare بمخزن Cloudflare الفعلي محليًا، وبيانات اختبار مؤقتة.

## التشغيل المحلي
انسخ `.dev.vars.example` إلى `.dev.vars` وحدد كلمة إدارة للاختبار فقط:
```bash
npm run dev
```

إذا كانت بيئة التشغيل لا تسمح لـ Wrangler بقراءة عناوين واجهات الشبكة، يظل اختبار `verify-runtime` مفيدًا دون خادم التطوير. لا تخلط نجاح اختبارات API مع اختبار بصري للواجهة أو ربط ماسنجر حقيقي.

## حدود النسخة الحالية
- لا واتساب، لا بوابة دفع، لا فواتير آلية، ولا إرسال حملات.
- الحد اليومي والشهري يستخدم UTC ويحسب المحاولات والتجارب؛ ليس حدًا ماليًا. حدد حد الإنفاق عند الوسيط أيضًا.
- حالة اشتراك نشط لا تعني أن الصفحة مربوطة. البوت يحتاج حالة active ومربع السماح بالتشغيل واشتراكًا غير منتهي وربطًا مكتملًا.
- الحد الأقصى 500 نشاط في نسخة التخزين الحالية؛ كل سجل منفصل لتجنب حدود حجم قيمة التخزين.
- الأسعار مسجلة يدويًا، وليست بيانات عن مبالغ محصلة أو أرباح.
- ذاكرة البوت آخر 6 رسائل؛ تبقى حتى الحذف. اتفق على سياسة الاحتفاظ قبل التشغيل التجاري. حذف بيانات محادثة يتم عبر POST `/api/clients/ID/contact-delete` مع sender، من جلسة الإدارة.
- طلب موظف أو مرفق يوقف الرد الآلي؛ الموظف يتابع صندوق وارد الصفحة. الرد اليدوي لا يوقفه تلقائيًا؛ استخدم لوحة تدخل الموظف.
- فشل إرسال ميتا أو غموضه يوقف المحادثة، ولا توجد إعادة إرسال تلقائية. قد يُفقد رد إذا تعطلت العملية بين إخراج المهمة من المخزن والإرسال؛ لا يوجد ضمان تسليم مرة واحدة.
- لا توجد تنبيهات أو لوحة تفاصيل لكل الرسائل في هذه النسخة.
- الخطة المجانية خاضعة لحدود حساب Cloudflare؛ استهلاك الوسيط مدفوع، ولا توجد ضمانة استخدام مجاني بلا حدود.

## Storefront and customer accounts

- `/`: public Arabic storefront; `/account`: customer dashboard; `/admin`: owner dashboard.
- Initial editable plans: 500/1000/2000 EGP per month, setup 1500/2500/5000 EGP. These are configurable sales prices, not payment processing fees.
- Customers register using email, phone and password (minimum 10 characters). Passwords use PBKDF2-SHA256 with individual salts and 100,000 iterations. Separate signed HttpOnly cookies isolate customer and owner sessions.
- Subscription requests snapshot the published plan server-side. Manual owner approval creates a 30-day subscription and preserves customer ownership. Activation stays disabled until page linking is configured. No online charge is made.
- Customer support threads are stored with each order. Owner can configure a WhatsApp contact number on the storefront settings page. Customer email is not yet verified; password reset and automated email notifications are not implemented.
- Limits: 1,000 registered accounts, 2,000 orders, 500 businesses, 100 messages per order. Accounts and order records use separate Durable Object storage keys.
- Run `npm test` and `node scripts/verify-runtime.mjs` to verify the bot and complete commerce flow inside the Cloudflare runtime.

## الرسائل والوسائط والحملات (v3)

افتح `/tools` من حساب العميل أو الإدارة. لكل نشاط ردود سريعة مستقلة تعتمد على كلمات تحددها، وتدعم النص والصورة والفيديو ورابط HTTPS. الرد المطابق لا يستهلك GPT؛ كل رد أو إرسال لحملة يحجز من حد الباقة. ملفات الصورة والفيديو يجب أن تكون متاحة لميتا عبر رابط عام مباشر. هذه النسخة لا ترفع الملفات ولا تنشئ صورًا أو تفهم الفيديو الوارد.

الحملات تُحفظ كمسودة وتبدأ يدويًا. المستلمون يُختارون من المحادثات الواردة فقط: موافقة موثقة وآخر رسالة خلال 24 ساعة. `اشترك` يسجل الموافقة، و`توقف` أو `إلغاء` يسحبها؛ لا يمكن للمشغل تجاوز إلغاء العميل. لا توجد آلية إرسال خارج نافذة 24 ساعة. الحملة تشمل حتى 500 مستلم، مع إسناد مستلم كل ثانية، وتحفظ حالة الإرسال أو التخطي أو تعذر التأكيد. لا تعاد محاولة الإرسال غير المؤكد تلقائيًا لتقليل خطر تكرار الرسائل. الحملة التي توقفت بعد إسناد رسالة لا تستدعي إرسالها إذا لم تبدأ بعد، لكن الإيقاف لا يسحب رسالة وصلت بالفعل إلى ميتا.

### الربط الفعلي

1. أضف App Secret وPage Access Token وVerify Token ومعرف الصفحة من قسم الربط في `/tools` كمدير فقط. يتم حفظها على الخادم ولا تعاد للمتصفح، ويظل البوت معطلًا بعد الحفظ.
2. في إعدادات تطبيق Meta، أضف Webhook الظاهر لكل نشاط وVerify Token نفسه، واشترك في أحداث `messages` للصفحة باستخدام تطبيقك وصلاحياته.
3. تأكد من `pages_messaging` ومهام إدارة الرسائل، ووضع التطبيق وصلاحيات الوصول اللازمة للعملاء الحقيقيين. إعداد ميتا واعتماد التطبيق يظلان مطلوبين.
4. أضف `OPENAI_API_KEY` إلى أسرار Worker واضبط رابط الوسيط والنموذج إذا أردت ردود GPT. الردود السريعة لا تحتاج المفتاح.
5. بعد اختبار Webhook وتوقيع الرسائل وصلاحية التوكن، فعّل الرد من ملف العميل وأرسل رسالة اختبار فعلية. الاختبارات المحلية تستخدم خدمات محاكاة ولا تثبت وصول رسائل حقيقية.

لتغيير بيانات الربط أعد إدخال جميع الحقول من الإدارة. لا تضعها في GitHub. سرعة GPT تعتمد على المزود؛ الردود السريعة تختصر طلب النموذج وتأخير الطابور السابق انخفض من ثانية إلى 50 مللي ثانية.

## القنوات الرسمية (v4)

يختار العميل أو المدير ماسنجر أو واتساب أو إنستجرام من `/tools`. معلومات النشاط والردود السريعة مشتركة للنشاط؛ المحادثات والموافقات والحملات والربط منفصلة حسب القناة. حدود الباقة مشتركة بين القنوات الثلاث. لا يوجد QR أو اتصال بحساب شخصي أو محاكاة لتطبيق الهاتف.

- **واتساب:** Meta WhatsApp Cloud API؛ حفظ Phone Number ID وWABA ID وAccess Token وApp Secret وVerify Token من الإدارة. Webhook: `/webhook/{clientId}/whatsapp`. سجل الرقم في Cloud API واشترك بالتطبيق في WABA وأحداث messages من إعدادات ميتا، بصلاحيات `whatsapp_business_messaging` و`whatsapp_business_management` حسب العملية. الربط اليدوي بالرموز مدعوم؛ Embedded Signup والتفويض بزر واحد ليسا مضافين.
- **إنستجرام:** Instagram API with Instagram Login للحسابات الاحترافية؛ حفظ Instagram Account ID وAccess Token وApp Secret وVerify Token. Webhook: `/webhook/{clientId}/instagram`. الصلاحيات: `instagram_business_basic` و`instagram_business_manage_messages`؛ اشترك في messages من إعدادات تطبيقك، وأتم متطلبات مراجعة التطبيق والوصول للحسابات الحقيقية. توليد التوكن وتفويض Instagram Login يتمان في إعدادات تطبيق ميتا حاليًا.
- اضغط تفعيل القناة من الإدارة فقط بعد التحقق من التوكن وWebhook وإجراء رسالة فعلية. حفظ بيانات قناة لا يفعلها. إيقاف القناة مستقل؛ مفتاح السماح بالبوت في ملف العميل يوقف كل القنوات. حالة الاشتراك والانتهاء والحدود تظل نافذة.
- إرسال النص والصور والفيديو والروابط مدعوم. الرسائل الواردة التي تحتوي وسائط بدون نص تحول إلى موظف؛ لا يتم تحليل محتوى الفيديو أو الصور. Instagram يستخدم `graph.instagram.com` وWhatsApp/Messenger يستخدمان `graph.facebook.com`.
- الرسائل العادية والحملات تقتصر على نافذة 24 ساعة والموافقة للحملات. واتساب وحده يدعم حملات خارج النافذة بقالب نصي معتمد وموافقة العميل. تُحمّل القوالب من WABA وتُراجع حالة الاعتماد عند إنشاء الحملة وبدئها. الإصدار يدعم قوالب BODY/FOOTER بمتغيرات مرقمة؛ قوالب الصور والأزرار والمتغيرات المسماة مستبعدة من الاختيار.
- قبول طلب الإرسال من ميتا ليس دليل وصول أو قراءة. حالات WhatsApp read/delivered لا تُستخدم لتغيير نتيجة الحملة في هذا الإصدار. لا توجد إعادة محاولة آلية للإرسال غير المؤكد.
- رسوم واتساب وحدود المنصات منفصلة عن الاشتراك والاستضافة واستهلاك GPT. إضافة دعم API لا تعني اعتماد التطبيق من ميتا أو اتصال حساب حقيقي بالفعل.

مراجع ميتا الرسمية: https://www.postman.com/meta/instagram/overview وhttps://www.postman.com/meta/whatsapp-business-platform/overview .
